<section class="page-hero"><div class="shell"><p class="section-kicker">CONTROLE TERRITORIAL</p><h1>Geofencing regional</h1><p>Antes de assinar uma operação, o app consulta o backend para confirmar se a localização pertence à região autorizada.</p></div></section>

<section class="section"><div class="shell">
  <div class="card-grid">
    <article class="feature-card"><h3>Área permitida</h3><p>Quando a trava está ativa, o usuário precisa estar dentro de ao menos uma área ALLOW vigente.</p></article>
    <article class="feature-card"><h3>Área bloqueada</h3><p>Qualquer correspondência com uma área DENY impede a transação, mesmo dentro de uma área permitida.</p></article>
    <article class="feature-card"><h3>Decisão auditável</h3><p>A autorização é curta, vinculada à carteira e operação e consumida uma única vez.</p></article>
  </div>
  <div class="safety-panel"><div><p class="section-kicker">PRIVACIDADE</p><h2>Localização somente quando necessária.</h2><p>O app pede localização em primeiro plano durante a ação financeira. Coordenadas exatas não são mantidas no estado público nem persistidas pelo backend.</p></div><div class="safety-list"><div><strong>Falha segura</strong><span>Sem precisão ou backend disponível, a operação não é assinada.</span></div><div><strong>Layer 3</strong><span>Uma autorização curta pode ser preparada para um único pagamento offline.</span></div><div><strong>Defesa adicional</strong><span>GPS deve ser combinado com integridade do dispositivo e análise de risco.</span></div></div></div>
</div></section>
